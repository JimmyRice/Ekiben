# kaisatsu-ffi

C ABI for [Kaisatsu](../../kaisatsu), usable from C, C++, Zig, Go (cgo) and firmware (Swift,
Kotlin and C# have idiomatic bindings in [`kaisatsu-uniffi`](../uniffi)). No heap allocation,
no handles to free, no global state: pass the trusted public keys and the scanned bytes, get
the claims back.

```c
#include "kaisatsu.h"

KaisatsuKey keys[] = {{ .public_key = { /* 32 bytes from /.well-known/kippu/ticket-keys */ } }};
KaisatsuTicket ticket;
KaisatsuStatus status = kaisatsu_verify(keys, 1, bytes, len, &ticket);
if (status != KAISATSU_STATUS_OK) {
    puts(kaisatsu_status_message(status));   /* ピンポーン🔔 BadSignature */
}
```

The header [`include/kaisatsu.h`](include/kaisatsu.h) is generated by `cargo xtask header` and
committed. [`examples/verify.c`](examples/verify.c) is a complete minimal gate; `cargo xtask
c-example` builds it and runs every shared test vector through it.

## Building

Release artifacts are built without the standard library, which keeps the shared library
around 65 KiB:

```bash
cargo build -p kaisatsu-ffi --no-default-features --profile release-small
```

This produces `target/release-small/libkaisatsu.a` and the platform's shared library. For
microcontrollers, add `--target thumbv7em-none-eabihf` (or your target) and link the static
library; set `CARGO_PROFILE_RELEASE_SMALL_OPT_LEVEL=z` to trade a little speed for size.

The default `std` feature exists only so that debug builds (which unwind on panic) link.

Kaisatsu verifies a ticket's bytes; how they travel from the buyer's screen to the gate (a
binary QR code, Base64, Base45…) is the integration's choice. If your scanner hands back
Base45 text, build with `--features base45` and define `KAISATSU_BASE45` before including
the header to get `kaisatsu_base45_decode`.
